# OpenValuationCase workflow

Build this workflow in the Copilot Studio visual designer. Do not create a local
`workflow.json` file.

## Security prerequisite

Configure both connector references as **Provided by run-only user**:

- Microsoft Dataverse
- Office 365 Users

Add Office 365 Users to the environment DLP policy in the same business data group
as Dataverse. The workflow derives the caller from `Get my profile (V2)`. Never add
caller email, role, or assignment as agent-supplied inputs.

The licensed-adjuster Dataverse security role must grant the minimum privileges to:

- Read and create owned `Valuation Case` rows.
- Read and create `Audit Event` rows related to accessible cases.
- Read the metadata needed by the Dataverse connector.

Dataverse row ownership and create permission are the authorization boundary. The
explicit `Assigned Adjuster` comparison prevents a caller who can read a team-owned
case from opening another adjuster's case.

## Trigger

Use **When an agent calls the flow** with one required Text input:

| Name | Description |
| --- | --- |
| `claimId` | Exact external claim identifier. Do not infer or generate it. |

Reject an empty value before calling a connector.

## Response

Use **Respond to the agent** with **Asynchronous response** set to **Off** under
Networking. Define these outputs:

| Name | Type | Value on success |
| --- | --- | --- |
| `outcome` | Text | `Succeeded` |
| `caseId` | Text | Dataverse Valuation Case row ID |
| `caseVersion` | Number | Persisted Case Version |
| `state` | Text | Persisted Case State label |
| `operationId` | Text | Correlation ID generated by this run |
| `continuationRequired` | Boolean | `false` |
| `missingFields` | Text | Compact JSON array, normally `[]` |
| `issues` | Text | Compact JSON array, normally `[]` |
| `artifacts` | Text | `[]` |
| `authoritativeValues` | Text | Compact JSON object containing claim ID and checkpoint |
| `displaySummary` | Text | Sanitized result for the adjuster |
| `isNewCase` | Boolean | Whether this run created the case |

Use compact JSON text for collection outputs because workflow response designers do
not consistently expose array and object types. Do not return raw Dataverse payloads.

## Designer actions

Rename every action as shown so expressions remain stable.

1. Add **Initialize variable** named `CorrelationId`, Type `String`, Value:

   ```text
   guid()
   ```

2. Add **Initialize variable** named `NormalizedClaimId`, Type `String`, Value:

   ```text
   trim(<claimId dynamic content>)
   ```

3. Add a condition named `ClaimIdIsMissing`:

   ```text
   empty(variables('NormalizedClaimId'))
   ```

   In the Yes branch, respond with `NeedsInput`, `missingFields` set to
   `["claimId"]`, `caseVersion` set to `0`, `continuationRequired` set to `false`,
   `isNewCase` set to `false`, and all other unavailable values set to empty text or
   empty JSON. End this branch.

4. In the No branch, add Office 365 Users **Get my profile (V2)** and rename it
   `GetCallerProfile`.

5. Initialize `CallerEmail`, Type `String`, with the profile's Mail value, falling
   back to User Principal Name:

   ```text
   toLower(coalesce(
     outputs('GetCallerProfile')?['body/mail'],
     outputs('GetCallerProfile')?['body/userPrincipalName']
   ))
   ```

6. If `CallerEmail` is empty, respond `Rejected` with this issue and stop:

   ```json
   [{"issueCode":"CALLER_IDENTITY_UNAVAILABLE","severity":"Error","retryable":false,"userActionRequired":true,"displayMessage":"Your authenticated identity could not be verified."}]
   ```

7. Add Dataverse **List rows**, rename it `FindValuationCase`, and configure:

   | Setting | Value |
   | --- | --- |
   | Table | Valuation Cases |
   | Select columns | `cca_valuationcaseid,cca_claimid,cca_casestate,cca_caseversion,cca_assignedadjuster,cca_checkpoint` |
   | Filter rows | Claim ID equals `NormalizedClaimId` using the dynamic query builder |
   | Row count | `2` |

   Prefer the designer's dynamic query builder. If an OData expression is required,
   escape apostrophes in the claim ID with `replace(value,'''','''''')` before
   inserting it into the filter.

8. Add condition `CaseExists`:

   ```text
   greater(length(outputs('FindValuationCase')?['body/value']), 0)
   ```

### Existing-case branch

1. Set variables from the first row returned by `FindValuationCase`: `CaseId`,
   `CaseVersion`, `CaseState`, `Checkpoint`, and `AssignedAdjuster`. For `CaseState`,
   use the Case State formatted label from dynamic content, not its integer value.

1. Compare the normalized assigned adjuster with `CallerEmail`:

    ```text
    equals(toLower(trim(variables('AssignedAdjuster'))), variables('CallerEmail'))
    ```

    If false, respond `Rejected` with issue code `CASE_ASSIGNMENT_DENIED`. Do not
    reveal the assigned adjuster's identity or any case details.

1. Set `IsNewCase` to `false` and continue to `WriteAuditEvent`.

### New-case branch

1. Add a Scope named `CreateCaseTry`. Inside it, add Dataverse **Add a new row**
    named `CreateValuationCase`:

    | Valuation Case column | Value |
    | --- | --- |
    | Case Name | `NormalizedClaimId` |
    | Claim ID | `NormalizedClaimId` |
    | Case State | `Candidate` |
    | Case Version | `1` |
    | Assigned Adjuster | `CallerEmail` |
    | Currency | `CAD` |

    Do not set Owner explicitly; the delegated Dataverse connection makes the caller
    the owner. Store the created row ID in `CaseId`, and set `CaseVersion` to `1`,
    `CaseState` to `Candidate`, `Checkpoint` to empty text, and `IsNewCase` to `true`.

1. Add a parallel Scope named `CreateCaseRejected`, configured with **Run after**
    for failed, timed out, and skipped `CreateCaseTry`. Respond `Rejected` with issue
    code `CASE_ACCESS_DENIED_OR_ALREADY_EXISTS`. This safely covers missing create
    permission and an alternate-key collision with a case hidden by row security.
    Do not retry creation and do not disclose whether a hidden case exists.

## Audit and success response

1. Add Dataverse **Add a new row**, rename it `WriteAuditEvent`, and set:

    | Audit Event column | Value |
    | --- | --- |
   | Event Name | `OpenValuationCase` plus `CorrelationId`, separated by ` - ` |
    | Audit Event ID | `guid()` |
    | Valuation Case | `CaseId` |
    | Operation | `OpenValuationCase` |
    | Before State | `CaseState` |
    | After State | `CaseState` |
    | Before Version | `CaseVersion` |
    | After Version | `CaseVersion` |
    | Actor | `CallerEmail` |
    | Correlation ID | `CorrelationId` |
    | Event At | `utcNow()` |
    | Details JSON | JSON containing only `claimId` and `isNewCase` |

1. Respond with `Succeeded`. Set `authoritativeValues` to compact JSON containing
    the persisted claim ID and checkpoint. Use one of these summaries:

    - New: `Valuation case opened in Candidate state.`
    - Existing: `Valuation case resumed in <state> state.`

The workflow reads existing state but does not increment Case Version or mutate the
case. It only creates a Candidate case when none is visible and authorized.

## Tool configuration

Use this agent tool description:

> Opens or resumes the valuation case for an exact claim ID. Always call this before
> any other valuation workflow and after a conflict. It returns the authoritative
> case ID, state, version, checkpoint, and whether the case was newly created. It
> rejects callers who cannot access or are not assigned to the case.

Configure `claimId` as required and filled from the user's exact claim identifier.
Do not allow generative filling of caller identity or authorization values.

## Acceptance tests

1. Empty claim ID returns `NeedsInput` and creates no rows.
2. Licensed adjuster opens a new claim: one Candidate case and one audit event exist.
3. Same adjuster opens the same claim again: the same case ID/version is returned and
   `isNewCase` is false.
4. A caller who can read but is not assigned receives `Rejected` with no case data.
5. A caller without create permission receives `Rejected` and no case is created.
6. Two simultaneous first calls produce at most one case because of the Claim ID
   alternate key; the losing call returns `Rejected` without retrying creation.
7. The workflow completes in under 100 seconds and the response action is synchronous.
